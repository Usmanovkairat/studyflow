# Manage assignments and completion

## Goal
As a student, I record, inspect, update and complete assignments.

## Acceptance criteria
- [ ] Task creation, list, detail, edit and delete work with real database writes and accessible forms.
- [ ] Fields are title, valid existing course, real required ISO due date, low/medium/high priority, todo/in_progress/done status and optional notes. Defaults are medium/todo.
- [ ] Trim title; reject blank or >200 characters, notes >5000, malformed dates, missing course and invalid enums while preserving useful form input.
- [ ] Toggle sets unfinished tasks to done and done tasks to todo. Editing can choose in_progress explicitly.
- [ ] Past dates are accepted. Missing IDs return 404; delete has confirmation, all mutations require CSRF and displayed text is escaped.
- [ ] Tests cover valid CRUD, completion transitions, all validation boundaries, 404s, escaping and persistence.

## Out of scope
Recurring tasks, attachments, subtasks and bulk mutations.

## Constraints
Depends on 01 and 02. Use tasks FK and enum constraints; routes in api.md. No schema beyond architecture.md.
